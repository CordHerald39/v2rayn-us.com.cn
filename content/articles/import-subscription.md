## 导入前确认格式

开发者订阅文档列出支持的协议标准格式及 v2rayN 内部格式。内部分享链接与普通节点链接用途不完全相同，不能假定它们可被所有客户端跨版本互认。订阅来源应明确提供 v2rayN 适配信息。

## 分组与更新分开确认

在订阅分组中添加一个可辨认名称，粘贴完整地址并保存，随后更新对应分组。不要把保存成功当作更新成功。记录更新时间、节点数量和错误原文，保留已有可用分组。

HTTP 错误优先检查接口与权限；返回网页优先核对地址；节点缺失则比较格式与版本支持。单纯重装客户端不能证明这三类问题会消失。

## 选择当前使用项

导入列表出现后，选择一个明确的节点作为当前项。核对它所在分组与来源，观察核心日志是否有启动错误。遇到缺少参数，不自行猜服务器端口、证书主机名或 Reality 字段，应回原服务配置核对。

## 各系统分别验收接管

在 Windows、macOS 或 Linux 上，系统代理如何被应用采用可能不同。开启客户端所提供的接管方式后，在一个固定应用建立新请求，记录目标、时间与客户端连接结果。一个平台成功不能证明另一个平台权限和网络设置已自动正确。

| 验收项 | 通过条件 |
| --- | --- |
| 下载与解析 | 更新无错误，配置字段完整 |
| 当前选择 | 选中项与测试记录一致 |
| 核心状态 | 无持续启动失败 |
| 实际连接 | 新请求与日志、出口一致 |
| 退出恢复 | 停用后基础网络符合原设置 |

测试失败时先恢复已知可用配置。只有某版本异常，需用相同网络、节点和目标对照，才便于判断升级影响。
