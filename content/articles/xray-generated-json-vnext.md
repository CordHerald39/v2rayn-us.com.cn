## 老路径找不到，先看生成格式
7.25.4 发行说明包含 Xray 核心配置格式调整，关联 PR #10132 的标题为 Remove vnext。对需要读取客户端生成 JSON 的用户，这意味着旧脚本依赖的层级可能已经改变。网页连通性和脚本提取结果属于不同验收项：客户端连接正常，旧解析脚本也可能返回空值。

## 区分三种 JSON
客户端保存的界面设置、客户端给核心生成的运行配置，以及你自己导入的自定义配置，不是可互换的文件。分析前记录文件来自哪里、由哪个版本生成、供哪个核心读取。不要用搜索替换把目录内所有 JSON 的 vnext 都删除。
对照 PR 中的实际代码差异和当前输出，再找你所维护脚本的字段访问位置。没有看到当前文件，就不应把某个旧教程的固定路径写成新版必然结构。

## 给维护脚本做可验证的修改
先保留旧输出与新输出的脱敏样本。让脚本遇到不认识的结构时明确报错，避免空字符串被当成“无服务器”或“删除配置”的依据。提取后至少检查目标地址、端口、协议以及相应认证字段的存在性和类型。
比较时不要在公开日志输出凭据。示例应使用合成值，真实配置只留在本地受控副本。需要同时支持两种结构的工具，应按明确结构分支处理，不能用找到的第一个同名键代替定位。

## 自定义配置不能自动获得全部迁移
发行说明描述的是客户端所生成的核心格式调整。你维护的外部 JSON 仍需按目标核心文档独立检查。若旧脚本直接修改生成文件，还要确认下次启动或切换配置是否会重新生成，覆盖你的改动。
完成标准是：脚本在对应样本上读取预期信息、未知结构得到清晰错误、客户端仍能启动相关核心。本文提供维护检查路线，没有运行你的脚本，也没有公布或测试真实配置。
